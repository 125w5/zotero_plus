# 研究模型路由修复

## 实际变更

- 移除 `openai.goldgom.top` 在配置、解析、研究助手和公式服务中的 Luna 单模型限制；用户指定的模型不会被静默替换。
- 可行性方案默认使用 `gpt-6.1-sol` / `high`，装配文字候选和全文评估默认使用 `gpt-6.1-sol` / `xhigh`。该默认只用于原来使用 Luna 的 OpenAI 或指定兼容网关。自定义服务和已经配置的其他模型保留。
- 公共对话模型增加“自动 · 按任务选择”，自动不再被错误地当成菜单第一项的手选模型；思考菜单增加“极高”。手选模型与明确提供的思考强度保留。
- `S.request` 根据实际服务生成 `reasoning_effort` 或 DeepSeek `thinking` 参数；启用思考时不额外发送温度。记录实际模型和思考强度。
- 图片说明、低价翻译、公式识别的默认路由保持原有模型，未触发已有文字、图片或公式缓存的重生成。
- 创新分析要求可编辑的候选研究路线、最近邻差异、证据缺口和可证伪验证；缺少条件集中在待补项，不能整栏用缺少定义替代研究分析。

## 验证与限制

`test/node/research-model-routing.test.mjs` 使用实际模型解析服务、公共请求服务和受控 SSE 回复，核对最终 HTTP 请求体包含模型和 `high` / `xhigh`，并核对显式 Luna/off、图片和翻译配置不变。模型、写作、公式、方案等 125 项定向测试通过；对话与准备的 66 项测试通过，PPT 与旧接口的 25 项测试通过（部分测试集合有重叠，不合并计数）。

这些测试验证程序路由和数据保护，不证明第三方网关账户已开通 Sol，也不证明创新分析内容已通过研究者质量评审。项目现有 API 指南仅记录旧 Luna/图片模型，未提供 Sol 别名。实际网关支持应通过其 `/models` 和受控短请求核对；不支持时必须报告真实服务错误，不能回落成 Luna 冒充完成。
