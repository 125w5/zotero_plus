# 素材驱动的论文补全

本轮保留 Zotero 中央标签页、原生 PDF 阅读器及现有日间/夜间配色。正文始终由用户审阅后写入，没有本地模型权重。

## 从前台复现

1. 在 Zotero 导入一篇有文字层的 PDF。打开“论文写作”项目，进入“论文装配 → 素材库”。导入后自动保存 PDF 文本块、章节线索、页码、坐标和文件版本，再通过现有 API 建议领域、方法标签。共享素材可以按标题、方法和原文搜索。旧文献可在“导入与自动整理”选择论文并重新整理。
2. 把素材拖入中央正文页。卡片上方是可点击的素材名，下方是结果目标。填写“解释这些方法的区别与适用边界”等要求，点击“补全正文”，或在目标框/正文内按 **Ctrl+Tab**。悬停卡片会展开各卡说明，移开后收起；颜色使用低饱和度渐变，并适配暗色。
3. AI 可以搜索共享素材库、读取原文和实验数据、检索 arXiv/PubMed 摘要、读取章节上下文、调用稿件检查。调用记录可在差异建议里展开。新来源先进入建议，确认后才关联到当前模块；缺少证据、来源版本变化、未知函数或无来源数字会阻止应用。
4. 查看原文与建议，点击“确认应用到当前模块”。**Ctrl+Z** 撤销，**Ctrl+Y** 重做。修改正文不会删除 Zotero 文献。公式、引用和 LaTeX 宏继续使用既有保护校验。
5. “论文结构”右键模块可添加章节、追加正文、删除模块；右键章节可添加后续章节或删除章节及子模块。删除章节先说明范围。Delete/F2/Alt+上下、模块多选与撤销继续可用；文本框右键仍保留普通文字菜单。
6. “证据网络”拖动顶部的 **↕** 调整证据阅读顺序，不改变正文段落顺序。每条链附说明，点击原文节点返回 PDF 对应页和区域。
7. 保存并关闭项目，重新打开后继续编辑。导出 DOCX 沿用既有检查、引用格式化、可编辑 OMML 和表格结构。

## 范围与限制

- 自动划分目前针对本机 PDF **文字块**。复杂多栏、表格、跨页段落可能需要用户调整；扫描件没有可提取文字时明确报错，不自动下载 OCR 模型。领域、方法是论文级 AI 标签建议，存于素材，不覆盖用户已有 Zotero 标签。
- 共享素材是长期研究资产。源 PDF 哈希相同时复用解析；变化时保留旧摘录与版本、提示下游重核，不覆盖用户写作。中断的整理任务可在重启后恢复；失败原因、重试位于“导入与自动整理”。
- AI 的函数能力是上述五类真实软件工具；没有开放任意脚本、任意文件操作或直接覆盖正文。每次最多四轮检索调用，避免无限请求。外部知识来自实际检索到的摘要，并保留 URL 和“仅依据摘要”标记；不代表已读取外部全文。
- Ctrl+Tab 仅在正文、素材目标和共创输入框用于补全；其他位置仍使用 Zotero 标签导航，Ctrl+Shift+Tab 保留反向切换。中文输入法组词时不拦截。
- 本轮减少了写作页重复的用途/参数按钮，其他工作台模块保持原有布局。

## 验收证据

原生测试从项目入口操作页面、拖动素材、输入目标、发送 Ctrl+Tab、审阅差异、撤销、右键删除、证据排序及导出；受控模型回复只用于使测试可重复，不等同于真实模型生成质量评价。

- Node：32/32（含五项工具调用、来源及取消测试）。
- Python：PDF 原文、坐标、哈希失效、无文字报错，以及 DOCX XML 三项测试。
- 完整 Zotero 前台组合回归：25/25；两个需要独立外部服务的可选测试跳过。
- 最后修正来源定位与失效传播后再次运行论文装配套件：11/11 通过。
