02
工作台、资料与对话

全局导航、原生文库与研究工作区的边界

当前产品是在 Zotero 原生文库上嵌入研究工作区。最左侧文件夹树仍由 Zotero 管理；研究对话、文献检索、论文装配、组会 PPT 是同一宿主中的功能入口。原生论文列表和研究页面可以切换，但不是两套独立的文献数据库。

文库中的真实附件路径由 Zotero 管理；研究页面中的卡片是对这些条目、附件或素材的引用。界面上看见论文标题，不等于本机已经有 PDF。下载列表还会验证本地附件及文件大小。

文件夹切换不是全局删除历史。每个范围可以拥有自己的会话记录，已导入的手工附件与文件夹自动资料分别保存。一个会话中移除文件引用，也不意味着删除原生文库里的文件。

本章依据当前源码核对入口和状态，不代表对每个原生窗口尺寸、第三方插件组合或当前安装包做了运行验收。

任务如何衔接

  1. 01选择原生文件夹
  2. 02进入主功能
  3. 03同步当前资料范围与会话
  4. 04预览、检索或编辑产物
  5. 05双击文件夹返回文库，或继续当前工作

各区域的职责

1最左侧功能导航与文件夹树
四个主入口位于原生文件夹树上方。集合选择决定当前资料范围；底部是日历与设置入口。集合名称、条目归属、附件与回收站仍属于 Zotero。
2原生文库工具区
“论文”“未关联资料”、全选、“语料库”“导入 Zotero”在文库顶栏提供。论文列表使用 Zotero 的筛选、排序与条目选择机制。
3嵌入研究页面
研究对话、文献检索和 PPT 共用持久化工作区 iframe。论文项目的准备页面按项目复用独立 frame，避免每次导航重新创建全部编辑状态。
4原生阅读标签
PDF 仍在 Zotero 阅读器打开。研究页面中的右侧资料详情负责摘要、图片、批注和线索，不另嵌一份 PDF 阅读器。

为什么这样设计

源码事实

原生文库负责文献实体，研究工作区负责会话、来源选择和研究产物。两者通过条目 ID、集合 ID 与附件 ID 连接。

设计解释

保留原生文件夹树可沿用用户已有文库习惯；共享 frame 减少切换时丢失编辑状态的机会。

源码事实

workspace.html 内仍存在旧版“文献研究、知识网络、论文写作”等静态导航和旧搜索控件。当前入口由 sidebar.js、library-workspace.mjs 与 ui/main.js 动态安装、替换或隐藏；不能根据静态 HTML 判断默认界面。

  • 接手时先定位当前宿主控制器，再修改具体页面，避免重新启用 legacy 静态导航造成双入口。
  • 验证单击文件夹切换本次资料、双击返回文库、返回原功能保留草稿三个动作，分别核对行为。
  • 不得把研究页面的 session、project、draft ID 当作 Zotero item ID；数据层需要保留各自身份。

当前边界与限制

  • 项目准备页面有自己的来源选择。切换外层文件夹不会自动重写既有项目的论文范围。

工作台、资料与对话

本次资料、文件留存、预览与拖动

共享第二栏将对话历史与本次资料放在一个可搜索区域。文件预览、勾选为模型资料、精选是三个独立操作。文件导入会保留真实文件和来源身份，拖动默认建立引用或复制讨论，不搬走原文件。

文件存放目录不是项目文件夹名称的简单磁盘映射。Zotero 集合决定文献组织，Zotero 附件存储决定物理路径；保存位置详情同时展示两者。当前导入会尽量把父条目或附件纳入会话绑定的可写集合。

当前自动同步文件夹资料只会默认勾选至多 12 项。其余资料可以留在目录中再由用户挑选，因此“文件夹有很多文献”和“这一次全部已发送给 AI”不是同一个状态。

语料库与 Zotero 文库导入

研究语料库保存可复用的完整文本、章节用途、标签及来源锚点。它用于按研究范围挑选并导入写作项目，不是把任意 AI 经验反复堆成无法核验的记忆。Zotero 文库导入是另一条原生文件导入流程，不能直接读取或合并别人的正在使用的数据库。

语料库是有范围的可复用来源集合，不承担科研项目复杂因果关系的自动证明。当前实现通过论文、素材、来源修订和项目约束保留结构化联系；它没有承诺只靠无限累计历史就能处理任意长期科研问题。

导出再导入 Zotero 文库适合跨库交换；不能直接选择另一台电脑的 sqlite 文件。导入后的题录与附件是否完整，须按原生 Zotero 导入结果核对。

阅读器的区域、来源与基本操作

阅读器以当前打开的 PDF 附件为来源。原文画布、速读、译文、图片证据和参考文献都必须绑定这个附件；同一论文的两个 PDF 版本不能只凭父条目相同而混用结果。这里负责阅读已有论文，派生笔记和解释不改写 PDF 文件本身。

  2. 02等待当前附件就绪

源码事实

源码事实

素材 ID 索引按 researchMaterials 的 branchRevision 缓存，避免每张图反复扫描全部素材；返回值仍克隆，防止前端改缓存对象。依据：assets.js materialFor。

迁移建议

实际 CPU、内存和首屏耗时需要另做性能采样；任务去重和有界队列是已实现机制，不能据此宣称全局卡顿已经根治。依据：在真实大文库和低配机器上记录首屏、切页、打字和停止任务的耗时。
