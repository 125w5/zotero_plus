# 论文速读、写作速读与完整素材：设计及验收（2026-10-14）

本轮以“面向写作的连续速读稿”为装配中间成果。它结合用户已经写下的内容和明确选择的真实素材，解释章节的论证安排、当前进度、拟补内容、结构和措辞调整，不自动填成论文正文。素材、正文、写作速读分别保存。已有局部改写候选及手动采用/还原仍保留。

## 两种速读的目的和语言

| 内容 | 已有论文速读 | 自己论文的写作速读 |
|---|---|---|
| 目的 | 判断论文做了什么、依据和适用边界、下一步读什么 | 说明本文将怎样论证、已经写到哪里、缺什么和怎样修改 |
| 语言 | 客观研究笔记，解释机制与条件，保留数值和比较对象 | 面向写作的连贯笔记，区分已写、拟补、待验证、结构与措辞调整 |
| 证据 | 本次实际读取的连续原文摘录、真实图表及说明 | 本章选定的完整素材、内部高亮/批注与已写正文 |
| 禁止混淆 | 作者声称 ≠ 已证明；摘要 ≠ 全文；图注 ≠ 已看懂图片 | 前人成果 ≠ 本研究结果；计划 ≠ 实验已完成；人工笔记 ≠ 原文事实 |

论文速读应回答具体问题、前人不足、核心机制与输入输出、假设、实验条件、数据集与基线、指标和重要数值、负结果与结论边界。没有原文支持时保留缺口，不用“显著提升”“有重要意义”之类套话补满。新的生成规则建议在来源足够时写 8–16 段、约 1200–2200 中文字；这些是提示要求，并非实际模型质量保证，也不是对短论文的字数门槛。

阅读器默认显示连贯正文与真实图表。公式图片及独立公式块默认隐藏，“显示公式”在原位置展开，切换不重新调用模型；正文中的必要行内变量保留。主题按钮提供简要内容，不隐藏正文、不作为跳转目录。生成语言版本升级与 PDF 来源缓存分开，已有人工速读修改的旧缓存继续使用，不被自动替换。

## 推荐工作流程

方向、检索、可行性和实验计划应迭代调整，不必完全串行：

1. 将宽泛方向缩小为对象、任务、场景和可检验的研究问题，先查少量近邻论文。
2. 分析数据、设备、时间、方法能力和伦理/使用条件，制定最小验证实验及失败后备方案。可行性分析要联系检索得到的实际论文。
3. 扩展检索。小问题可先覆盖十几篇，宽方向可覆盖几十篇；数量是安排而非软件门槛。综述、最近邻工作和不同结论都应覆盖。
4. 精读少数核心论文。优先依据问题相关性、方法可理解性、证据完整性、复现条件和反例价值筛选，而非只按影响因子。
5. 选择研究类型和目标刊物接近的范文，分析段落功能、论证顺序、图表位置和表达习惯，保持来源归属。
6. 同步开展实验、保存完整素材、整理内部高亮与批注。按本文章节的写作用途组织，不改变前人原文所在章节。
7. 装配写作速读：结合素材和已写正文形成连续、分章节的论证稿；正常保留“尚未写入”“待验证”“缺素材”。
8. 人工完成正文，必要时明确调用局部改写。比较差异，选择采用或保留原文，核对数字、公式、引用和限定条件。
9. 检查整篇结构与一致性，再用已有验证/导出流程输出正文 Word 和执行方案 Word。

## 章节不能混用同一种生成规则

| 章节 | 写作功能与表达要求 |
|---|---|
| 引言 | 场景 → 具体缺口 → 问题和目标；控制背景，不提前宣布未得到的结果 |
| 相关工作 | 按路线和条件比较，说明最近工作的关系，避免逐篇罗列摘要 |
| 方法 | 对象、变量、假设、输入输出、步骤和设计理由；前人方法保持归属 |
| 实验 | 数据划分、防泄漏、基线/消融、参数、设备、指标和复现条件；区分计划和已实施 |
| 结果 | 实际数值、单位、比较对象、图表和条件；未完成实验列为待验证 |
| 讨论 | 区分观察、解释、推测，比较前人并说明适用边界 |
| 结论 | 对应实际完成的研究目标和已有证据，不扩大论断或引入新结果 |

原文所在章节与写作用途分别记录。例如前人方法的条件段可以支撑本篇引言中的研究缺口，但不能自动变成用户自己的方法或结果。

## 完整素材与内部批注

完整段落或章节素材保留一个身份，不按句子拆卡。局部标注记录逐字引用、起止位置、前后文、来源哈希和版本；空白换行可以归一匹配后映射回原文。重复句必须借助前后文定位，无法唯一确定时拒绝猜测。选中原文后可写批注和保存高亮，重开可查看或移除；内容和来源锚点保留。

标注是阅读提示，不能充当独立论文证据。来源发生变化时保留旧标注并提示待核对，不静默移到另一个位置。本地素材与发布到素材库的素材都通过原来的存储入口保存。

## 连续写作速读的更新

中心画布可在“素材／写作速读／正文”之间切换。写作速读按章节连续阅读；一个完整论证单元可关联一段或连续几段正文以及若干完整素材。每单元有连贯笔记、已写内容、拟补内容、结构与措辞建议、证据和待补问题。辅助安排默认折叠，保持文章阅读感。

首次可生成整篇；后续可以更新当前单元、更新这一节或检查整篇。具体规则：

| 变化 | 本地处理 | AI 范围 |
|---|---|---|
| 字体、粗体、空间等显示格式 | 保存显示设置 | 不更新速读 |
| 正文内容、论断强度变化 | 自动保存，标记关联单元待更新，保留旧速读 | 用户选择相关单元/章节后局部更新 |
| 未使用素材加入素材库 | 保存素材 | 不更新其他单元 |
| 已用素材或批注改变 | 标记使用它的单元 | 对应正文、来源摘录、章节规则和相邻速读概述 |
| 增删、重排或关联改变 | 标记结构或邻接单元待检查 | 本章重新梳理；跨章节关系通过整篇检查 |
| 人工改过速读 | 原文保留 | 更新成为红删绿增的建议，可保留更改或保留人工版本 |
| 请求途中再编辑 | 内容继续保存 | 旧回复不得覆盖新版本 |

局部请求不会携带其他章节的全文和未选择资料；已写正文通过有界摘录传输并记录读取范围。内容指纹按完整来源和正文核验，不能仅凭项目 revision，也不能仅按变动字数判断。未变化的内容指纹复用，输入时不发起模型调用。Auto/Ask、所选模型和推理强度继续沿用现有对话偏好。

全文检查针对当前写作速读的研究问题、章节衔接、方法与结果关系和论断强度，给出 2–3 个用户可选方案。它不冒充对全部原始论文的事实核验，也不直接改正文。核验之后内容再变动，检查标记过期。

本轮实现主动更新与本地待更新标记；没有开启“停写几秒即请求模型”的自动更新，避免编辑时重复付费请求与延迟。

## 可以参考的开源项目

以下仓库的 README 在本轮已读取，设计借鉴而未复制其代码：

| 项目 | 建议重点 |
|---|---|
| [Open Notebook](https://github.com/lfnovo/open-notebook) | Notebook、来源、笔记、资料范围控制、可配置转换和引用；优先读 notebooks-sources-notes 与 transformations 文档 |
| [Scim](https://github.com/rayfok/scim) | 按内容类型辅助阅读、分布式高亮与可调密度；阅读器及 skimming 模型 |
| [Hypothesis Client](https://github.com/hypothesis/client) | 选区、文本锚定、前后文与批注；适合完整材料内部标注 |
| [Zotero Better Notes](https://github.com/windingwind/zotero-better-notes) | 笔记模板、链接与批注进入笔记的流程 |
| [STORM](https://github.com/stanford-oval/storm) | 检索、提问、资料整理与提纲分阶段；百科用途不等于科研结果可以自动补写 |
| [GROBID](https://github.com/grobidOrg/grobid) | PDF 章节、参考文献和坐标结构化；写作用途需要自己的证据与章节规则 |

NotebookLM 可参考其来源选择、引用定位、保存笔记和 Studio 中间成果的组织方式；它不是开放源代码的参考仓库。[官方帮助](https://support.google.com/notebooklm/answer/16179559?hl=en)。Open Notebook 更适合实际阅读源码。阅读深度可参考 [Keshav 的三遍阅读法](https://systems.cs.columbia.edu/ds2-class/papers/keshav-paper.pdf)，表达模板可参考 [Academic Phrasebank](https://www.phrasebank.manchester.ac.uk/) 的功能分类，不机械拼接范文原句。
