# 阅读器译文与公式验收（2026-09-28）

本轮在现有 EasySch/Zotero 单程序内改进阅读器，不引入第二个 PDF 阅读器或本地模型。实际启动 WisPaper 观察了“论文 / 译文”切换、缩略图、原文与译文并排的交互；未复制 WisPaper 程序文件、源码或素材。

## 已实现

- Zotero 原生 PDF 标签增加“译文”入口。译文留在同一阅读标签内，当前 PDF 页与译文页同步，宽度可拖动并保存；每段可展开原文、定位 PDF。译文按页面双栏阅读顺序排布，正文先出现，图片索引异步补入。
- 识别到的行间公式单独显示 PDF 原式图，优先读取高清原图，失败时回退缩略图；不把这些原式送入机器翻译。只有文字提取而无公式图时，原式用数学字体显示并提示核对。与原式同处的孤立公式编号合并显示。
- 已配置机翻时优先用快速机翻；否则使用 API-only 的 GPT-6 Luna。对第三方 OpenAI 兼容网关，明确使用流式响应并校验结果完整性。用户给出的站点根地址自动规范为 `/v1`。
- 素材库可生成概念示意图。图像以“AI 构想 / 非论文证据”入库，不当作真实论文或实验结果。AI 与图像凭据分别存于本机 Zotero 密码管理器；代码与 Git 提交不包含密钥。

## 验证类型

- **真实 Zotero 前台 + 真实模型：** 在隔离验收文库打开 C-AMC PDF，第 3 页译文显示 9/9 处中文正文；第 5 页显示中文段落及原式图片。图像生成入口在前台生成并入库一张构想素材，数量从 1610 增至 1611，状态明确为“非论文证据”。
- **真实 API：** GPT-6 Luna 网关返回中文与结构化 JSON；图像网关返回可读取 PNG。该调用与受控回复测试分开记录。
- **原生自动测试：** `researchReaderInteraction` 15 项通过，包含实际 PDF 阅读器实例、受控双栏/公式顺序和慢图片索引；`chat-completion` 4 项、`image-generation` 8 项通过。
- **尚需前台复查：** 最新的孤立编号合并改动已构建，桌面工具因检测到正在进行的输入拒绝再次操作窗口；因此最终公式编号去重的真实鼠标验收暂不标记通过。

## 限制

公式识别依赖 PDF 文字提取与图片索引；扫描页需 OCR，长公式及行内混排公式仍可能需要人工核对。源定位在索引信息不足时只能落到所在段落。机器翻译用于阅读辅助，不等同出版级学术译稿。
