# 阅读准备与素材后台队列性能修复（2026-10-28）

本轮仅修改准备时机、重复工作和队列调度。没有删减速读、图片证据、译文或章节素材能力，没有清除已有生成文字、图片和人工修改，没有访问日常文库内容。未构建、安装或打包。

## 查明的开销

1. `assets.index()` 原来只合并进行中的提取。一次提取结束后，工具栏、速读或图片页再次请求同一个 PDF，仍启动 `assets-index` 外部引擎、解析结果并重新装配全部图表元数据。共享提取完成后，多个调用方还各自修改同一结果对象。
2. PDF 工具栏构造时立即启动本地索引、全文译文准备和速读准备，与阅读器首屏争用执行时机；启动恢复又遍历所有恢复的 PDF，包括没有显示的标签。
3. 已完成图片也经过全局图片队列。当前论文的本地缓存可能等待其他论文的图片生成任务，才返回给已完成的速读。
4. 附件的 `modify` 通知不代表 PDF 内容发生变化。原素材队列没有按文件签名跳过，重复发布 `queued/running`、启动图表和译文链。自动阅读准备也会重新进入已完成论文的来源与速读缓存链。
5. 章节素材任务虽然串行，原 `queueArticle()` 却在入队时就为每篇启动图片与 `prepareTranslation()`，因此批量导入仍会同时展开多篇本地准备。
6. 重启后已有完整来源快照，仍创建完整副本并序列化比较，才能确认无须写回。

## 当前行为

- **先显示阅读器，再后台准备。** 三处工具栏准备均让出 180 ms；关闭或隐藏的恢复标签不启动该次准备。恢复时只预热当前阅读的 PDF，切换标签时再预热新选中的论文。直接点击速读、译文、图片证据的操作仍可立即请求准备。
- **按文件签名复用已完成索引。** 同一个附件、相同文件大小与修改时间复用内存中的已完成图表索引，不重复启动提取引擎。并发首次请求只提取并装配一次。PDF 改变、显式刷新或人工裁切后可重新提取；迟到的旧请求不能覆盖新索引。
- **已完成内容走读取路径。** 同签名完整图表直接返回；自动预热已持久完成的论文不再进入来源/模型链。直接打开内容页仍读取最新持久内容，保留直接刷新或人工修改后立即可见的行为。
- **后台队列按篇准入。** 章节素材队列只有一篇进入执行，轮到该篇时才启动其独立图片和译文链。后续优先当前阅读论文，其余按原入队顺序；篇间分别让出 180/350 ms。已经运行的模型请求不因切换标签被无故中止，以保留已发生的工作。
- **同文件的素材通知不重复整理。** 已完成索引记录文件签名；匹配的后续通知不会改回排队状态，不会启动三条处理链。文件改变或明确强制整理仍进入正常处理。
- **可以取消排队任务。** 取消会立即移出等待队列、转为部分完成/已停止，不遗留假的排队状态；不会启动该篇的图片或译文准备。取消某个附加观察者不会误取消原有后台任务。
- **不重复比较完整来源快照。** 已验证来源缓存与提取指纹一致时，不再重新序列化同一份全文。

测试使用实际 JS 模块和受控本地引擎/模型替身验证调用次数与取消协议，不读取日常论文，也不消费模型额度。关键回归包括：

| 场景 | 可核验结果 |
| --- | --- |
| 同文件工具栏/速读/图片重复请求 | 仅 1 次提取引擎调用 |
| 首次并发请求 | 提取及元数据装配共享同一结果 |
| 更换 PDF、明确刷新、人工裁切 | 正常重新提取；旧结果不覆盖新结果 |
| 恢复 2 个 PDF 标签 | 只准备选中的 1 个；切换后准备另一个 |
| 180 ms 等待期间关闭标签 | 没有来源、图片或模型请求 |
| 3 篇素材整理排队 | 开始时只有第 1 篇启动图片/译文链；正在阅读的第 3 篇下一次优先 |
| 同文件完成后连续 6 次素材通知 | 0 次新写入、章节处理、图片请求或译文准备 |
| 同文件完成后连续 8 次自动预热 | 0 次新来源/模型链请求或写入 |
| 取消等待的自动素材任务 | 立即移出队列；没有新图片/译文调用；无虚假 queued 状态 |
| 阅读准备成功、模型失败、取消 | 进度任务均关闭，活动计数归零 |
| 应用服务重启、修改模型偏好、恢复图片元数据 | 已保存正文和人工修改保留，不重新生成速读 |

相关修改文件均通过 `node --check`。以上结果验证消除重复启动和排队竞争的行为，不等于已完成真实文库上的帧率、首次阅读耗时或整机 CPU 基准。首次没有任何缓存的论文仍需提取和生成；现有持久缓存不会因此被删除或自动重写。素材整理已经运行的单篇请求仍由原有提供方超时与取消机制收尾。
