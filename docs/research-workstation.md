# EasySch 源码内置科研工作台

论文 AI 的正式架构以 [论文核心架构决议](paper-core-architecture.md) 为准：默认继续使用已配置的 DeepSeek，论文 Agent 与统一证据协议属于核心路线；远程专用权重可切换。该决议明确区分已运行能力与待集成服务。

## 产品方案

围绕研究生的收集、筛选、精读、证据整理、组会汇报、导师追问和写作组织功能。保留 Zotero 文库、标签、笔记、全文检索、PDF 阅读器及引用引擎；不另建 Electron 外壳或重复数据库。

小绿鲸截图值得借鉴的是论文、翻译、结构化笔记同时可见，以及按科研场景组织入口。参考 https://www.xljsci.com/ ，不以未验证的用户数、训练规模作为设计依据。短视频链接无法读取，未声称观看。期刊指标参考 https://github.com/MuiseDestiny/zotero-style 和 https://github.com/redleafnew/zotero-updateifsE 的能力边界；数据必须带来源和年份，缺失时留空，不能让模型编造。

## 代码边界

- `xpcom/research/`：原生生命周期、独立 SQLite 数据、指标、DOCX、工作流及既有 AI/导出服务。
- `content/zotero/research/`：工作台 HTML 与按功能拆分的 UI；通过主程序 chrome 包加载，不需要安装 XPI。
- `itemTreeColumns.jsx` 和 `itemTreeRow.js`：原生列定义及数据读取。保留第三方自定义列 API。
- `fulltext.js`：DOCX 提取结果写入原生全文缓存及索引，复用高级搜索。
- Word 安装器：自动安装前检测 Word；无 Word 静默跳过；手动安装保留诊断。

研究数据存入当前数据目录的 `research.sqlite`，以 libraryID/itemKey 关联原文库，不更改上游同步协议。指标按 ISSN、年份、来源保存；阅读状态单独保存；生成内容继续保存在 `easysch/workspace.json`，兼容之前的草稿。两者都是本地数据，尚不随 Zotero 云同步。迁移采用事务和版本检查，不将新指标塞进 Extra。

## 交互与数据原则

提供日常整理、文献筛选、组会准备视图。本次按用户要求一次性应用科研标签布局，此后通过菜单明确选择视图切换。原生拖拽、显示隐藏和排序继续有效。指标导入明确年份及来源；个人 API 密钥使用密码管理器，不进入导出或源码。

阅读器保留原生渲染和批注，新增同一窗口中的科研侧栏。模型请求由用户操作触发，答案必须引用采集到的证据。DOCX 定位使用段落而非虚构页码；表格、脚注、批注与正文分开解析，修订删除文本不进入正文，文件不被改写。

组会独立保存主题、时间、文献、时长和导师关注点。大纲确认后才导出；导师模式记录连续问答，问题与会后任务可回写。生成内容是待核对草稿，不作学术事实来源。

## 分阶段验收

1. 原生列表列、指标数据库、科研侧栏、DOCX 原生索引、Word 检测以及完整源码构建。
2. 集成 AI 精读和现有写作导出能力，组会项目及连续追问。
3. 图表抽取和证据定位增强、矩阵、多条件筛选与冻结列。
4. Word 修订及侧栏、LaTeX 项目编译和 SyncTeX、多端同步。

阶段不是完成声明；验证结果另记。仅在实际行为测试通过后标为完成。保留主仓库和子模块真实上游来源；未获得用户的 Fork 地址前不伪造远端、不改写 `.gitmodules`。

服务适配按 providers.js（凭据、签名与连接）、search.js（公共学术检索）、metrics-provider.js（期刊指标）、columns.js（标签与时间渲染）划分。工作台检索 UI 独立放在 ui/search.js。
