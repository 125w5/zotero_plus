# EasySch writing flow v3 — connected chapter rapid read + task plan (implementation spec)

Paths: R = chrome/content/zotero/research, X = chrome/content/zotero/xpcom/research. Background designs (read the parts you need): scratch/results/wf_1db-design_reuse-first.json (file:line plan), wf_1db-design_research-thread.json (spine, effects, origins), wf_1db-design_researcher-workflow.json (UX, task seeds, risks), maps wf_1db-flow-contracts.json, wf_1db-corpus-usage.json, wf_1db-rapid-read-and-draft.json.

## User intent (authoritative; overrides the handbook where they conflict)
1. Stages must connect: the feasibility plan concretely guides material assembly, direction discussion, the read and the tasks; later stages refine and divide the work per chosen direction and per chapter.
2. The research corpus is used from preparation to tasks.
3. Assembly = generating a rapid read (速读). The main output is a very detailed, evidence-bound rapid read organized by the project's chapters, plus an optional, clearly ordered task plan that the user executes.
4. The app never generates paper prose. 5. The old design was over-modularized: give every stage ONE shared context accessor instead of separate copies. 6. Keep the visual style, the four-stage frame and existing components.

## Architecture
- One accessor: new R/shared/research-thread.mjs exports `threadContext(project, notebookState, {sectionID, corpusRows, readings, decisions})` returning {scope, plan (presented snapshot + versionID/status), chapters:[{sectionID,title,purpose,task,hypotheses,experiments,evidenceNeeds,closest}], decisions (active, incl. direction decisions), structureOutline (structure-reference paper outline, non-citable), corpus summary, digests{scope,plan,assignment,decisions,sources}}. Every prompt builder (direction, chapter read, selection/refinement context, task plan, chat summary) uses it. writingPreparation (R/shared/writing-framework.mjs:29-33) becomes a thin wrapper over it and its bugs are fixed (reads of nonexistent researchQuestion/experiment, dropped plan.closest, 1800-char truncation of plan fields).
- Storage stays additive; no destructive migration. Large or frequently edited records live in their own branches so a status click does not re-save a 3 MB project: `projectReadings[projectID] = {version:1, chapters:{[sectionID]: ChapterRead}, edits:{}, at}` and `projectTaskPlans[projectID] = {version:1, basis{planDigest,decisionDigest,readsDigest}, items:[Task]}`. Use E.store.update on one entry (the store encodes per entry). Read with E.store.peek.
- Small additive fields: plan.chapters[{title,task,hypothesisIDs,experimentIDs,evidenceNeeds,closestQuoteIDs}] (validated against the structure and existing plan IDs; unknown dropped); version.corpusRevisions{entryID:revision} checked by N.stale; notebook decisions rows gain {origin:'direction', questionID, discussionID}; researchPreparation.chapterPlan[{sectionID,...}] and corpusIDs; preparationSourceSelection.corpusIDs (absent = all scope-matching corpora except the auto project corpus).
- ASSEMBLY_FLOW_VERSION may become 3 only if migrateAssemblyFlow never resets ui.step or data for v2 projects (today a bump resets ui.step, R/shared/assembly-direction.mjs:31). Stage labels: '素材装配','方向讨论','速读细调','内容导出'. Update UI tests that assert the old label.
- Model calls: E.studio.request (X/ppt-studio-ai.js; keep its (prompt,input,status,signal,options) signature) with aiAction 'evidence_organize' and model purpose 'framework' for chapter reads, 'direction' for direction questions, 'plan' for task-plan wording. One call per chapter, AbortController per run, progress text, basis re-check before save, one repair retry. Avoid phrasing that trips the authorship regex (R/shared/research-ai-policy.mjs:24-27, e.g. '生成我的论文…'); you do not own that file.

## Stage behavior
1 Preparation (notebook.html 准备): status line shows usable corpora and entry counts; a corpus picker (reuse the corpus page or a small dialog) saves preparationSourceSelection.corpusIDs; selection joins preparationInputs and inputSignature. Stop the automatic project-corpus rebuild on every assessment/assembly entry (X/notebook.js prepareProject/collect path, X/research-resources.js:25-37); keep the explicit 导入当前装配.
2 Feasibility (可行性方案): PLAN_RULES (R/shared/academic-prompts.mjs) emits chapters bound to the user's structure; validatePlan (R/shared/academic-plan.mjs) checks titles/IDs; 章节任务 (R/notebook.mjs:40) shows real chapter tasks with linked H/E titles instead of echoing structureDraft; older plans fall back to section purpose. Close-read papers rank first in the 18-source budget; up to 6-8 ranked corpus rows join sources via source() with a 语料库 coverage label. Remove the duplicated RESEARCH_AI_RULES/verbatim-quote conflict in SOURCE_RULES (AI-12) and say 比较本地已选文献中的接近工作与反证 unless an explicit 联网补充接近工作 toggle calls evaluate with online:true (AI-17). Fix the 3 failing tests in services/research-engine/test/notebook-discussion-boundary.test.mjs (decide whether code or fixture is stale; keep product behavior documented in the handbook).
3 Enter assembly: copy chapterPlan/corpusIDs into researchPreparation; a stale plan asks 继续已有装配 / 先更新方案 instead of silently resuming.
4 素材装配 (stage 1): matching (R/shared/material-section-matching.mjs) uses chapter tasks (match reason cites the task, e.g. '对应 方法 · 验证 H2/E2') and accepts corpus rows as candidates (copied into project.materials on apply with deterministic id 'corpus-'+entryID, corpusID, corpusEntryID, materialID, sourceRevision). Primary action 生成装配速读 builds the first chapter read from plan slice + chapter materials + ≤6-8 ranked corpus rows + the user's own block text (as 已写, not as source evidence) + structure outline (non-citable).
5 方向讨论 (stage 2): questions derive from plan.openQuestions/pending/route alternatives/closest-work objections/chapter read gaps; each carries origin {type,ref} and each option carries effects {keepHypothesisIDs,deferHypothesisIDs,keepExperimentIDs,deferExperimentIDs,emphasis,sectionIDs}. Confirmed answers append notebook decisions. The last button becomes 确认，按方向更新速读 and refreshes only the chapters whose basis changed. Remove the auto-draft after the last question (R/manuscript/direction-workspace.mjs:64). Re-stamp a legacy-matching discussion once so migrated projects are not forced to re-discuss.
6 速读细调 (stage 3): canvas shows the read in the reader's 速读 presentation (reuse classes/markup of R/shared/reader-rapid-reading.mjs and R/shared/reader-reading-surface.css; extracting a shared view module is fine). Per chapter: title + state chip (当前/待更新/未生成/有更新建议); 本章任务 line with route chips (采用 H2 · 暂缓 E3 · 方向第1题); a 40-120 字 brief; detailed nodes [{id,role:goal|evidence|method|link|gap,claim,status:supported|planned|missing,narrative,evidence[{quoteID,sourceID,materialID|corpusEntryID,quote,start,end,page}],planRefs,decisionRefs,questions}] with [素材 · PDF 第 n 页] chips; figures/tables/formulas of linked materials after the citing node (formulas hidden by default); 缺口待办 list. Depth scales with evidence (≈1500-3500 字 per chapter when excerpts allow). supported nodes must bind client-assigned W excerpt IDs to exact substrings (reuse writingEvidenceExcerpts / bindRapidReadingEvidence logic); planned/missing nodes claim no results. Number guard: numbers must appear in bound quotes, plan or chapter metadata; drop failing nodes, not the chapter (AI-10 spirit). Edits: double-click edits a node (overlay {originalText,text,editedAt}, 恢复 AI 解析); regeneration of an edited node becomes pendingUpdate with a red/green diff. Selection on a node offers 解释 / 忠实改写 / 核对原文 with number/LaTeX guards and preview-before-accept. A 查看速读 / 查看正文 toggle keeps the user's own editor and blocks fully usable; user block text is never overwritten.
7 内容导出 (stage 4) + task plan: optional 整理任务计划. Deterministic seeds from plan.minimumValidation, kept experiments (data/preprocessing/controls/comparison/metrics → steps; support/refute → acceptance; cost → estimate basis; outputs → deliverable), pending, open questions, direction decisions (deferred work dropped), read gaps, unplaced corpus entries to verify. One model call only orders/merges/words them. Task {id = hash of seed IDs (status survives regeneration), order, phase (最小验证/实验与数据/证据补齐/图表与核对/写作整理/导出检查), title, goal, steps 1-8, deliverable, check, hours{min,max}, assumptions, dependsOn (acyclic, earlier only), sectionIDs, planRefs, gapRefs, decisionRefs, evidenceRefs, tool, status todo|doing|done|skipped, note, doneAt}. Cards: numbered, 先完成 #i, 开始这一步 (jumps to chapter/evidence/tool), checkbox. Never drop done or user-added tasks. Export 导出速读与任务计划 Word through the existing document engine (X/export.js, services/research-engine/manuscript/document.py 4-block task layout) to a new file, never overwriting; add the hidden 导出引用资料包 (BibLaTeX/Markdown) action back to this stage (feature F08). Manuscript export of the user's own text stays as is; whole-text assessment stays optional (评估我写的正文).
- Retire as default entry points (keep code paths and stored data readable): per-block prose drafting A.prepareDraft and 生成初稿候选, 'assemble' block prose candidates, 整篇调整. Legacy draftBatch/proposals keep their existing review controls; no new ones are created.
- Daily loop: project card shows '任务 d/n · 下一步…'; stage bars can pin the next three ready tasks.
- Corpus end to end: one accessor `E.corpus.projectRows(projectID, {sectionType, query, limit})` in X/research-resources.js reading corpora via E.store.peek, scope-checked, returning material-shaped rows {id:'corpus-'+entryID, corpusID, corpusEntryID, originMaterialID, sourceRevision, kind (paper-derived keeps its material kind, manual → note), title, sourceText, sectionType, paperItemID, anchor, coverage:'语料库 · …'}; projectID null = all corpora (for chat). Fix corpus-library.mjs coercion of unknown sections to 引言 (use 未分类), edited source entries become origin:'manual' keeping originalText (F10), corpus creation gains domain/keyword fields and manual entries skip or warn on scope (F09). Dedupe imports by corpusEntryID and origin materialID.

## Contracts
- Performance: never E.store.get() without a path; read-only paths use E.store.peek / A.assetLibraryView() / A.asset(id) / A.allView() / N.materialsView(id) (shared frozen objects; clone before adopting). Cache per-source digests; never hash or clone all materials per render. Coalesce reading-edit writes.
- Evidence honesty, preview-before-accept, staleness and cancel guards stay. AI discussion and AI images are never evidence.
- Style: reuse existing classes/tokens; new CSS only in FLOW-owned or new files; no restyling.
- Tests: Node tests for threadContext, plan chapter validation, corpus accessor/dedupe/provenance, matching with chapter tasks and corpus rows, direction derivation and effects, chapter read validation/merge/pending/overlay, task seeds/order/id stability/status carry-over, migration (v2 projects keep step, blocks, draftBatch readable), and the 3 notebook boundary tests.
